# 《谁是卧底》（Who is Undercover?）

基于现代 Web 技术开发的联机桌游《谁是卧底》，支持线上多人联机对战和线下联机发牌两种游戏模式。项目具备法官裁判天眼控制台、实时描述计时器、断线重连、自适应卡片等丰富特色。

## 🌟 项目亮点与功能特性

### 1. 游戏模式
- **线上模式 (系统流转)**：系统自动挑选词汇对并分配身份角色，控制玩家发言顺序与倒计时（限制1分钟，超时自动过麦），并主持全员投票与结算。
- **法官模式 (房主观战)**：房主可以在线选择亲自参赛或作为“法官裁判”观战。
- **线下模式 (联机发牌)**：支持玩家使用手机在线看牌（分配词汇与身份），但在现实中面对面进行发言讨论和投票，并由法官在系统上同步记录淘汰状态。

### 2. 核心机制优化
- **法官天眼控制台 (线上模式)**：对于充当裁判的非参赛房主，在游戏进行中提供双列高级天眼面板，实时掌控所有人所持词汇、身份阵营（平民/卧底）及存活状态；同时对参赛玩家深度脱敏，禁止提前窥视身份与他人词汇。
- **玩家身份防偷窥**：游戏过程中，参赛玩家的秘密词卡仅支持“长按/按住查看词汇”，且彻底隐藏 `角色: 卧底/平民` 的直接标签。卧底严格定义为该局内分配词汇数量占比最少的一方，玩家只能通过发言描述逻辑去推断。
- **流程双级跳转**：最后一轮结束结算时，系统先引导全体玩家进入结算页面（展示该轮词汇及胜负），待法官确认完毕后点击“查看终极排行榜”，才会同步切入终极积分榜和领奖台，确保了流程的平滑过渡。
- **Session 自动清理**：弃用 `localStorage`，全部迁移至 `sessionStorage` 驱动。每个临时玩家与昵称紧密挂钩生成随机后缀临时 ID。一旦用户关闭当前浏览器标签页或窗口，会话即刻销毁，后端3秒宽限期超时后自动踢人清理，绝无数据残留冲突。

### 3. 词汇库精细化管理与历史备份
- **双栏管理面板**：提供包含实时搜索检索、词库名称及描述修改、添加/删除词对的自适应编辑界面。
- **每日自动快照备份**：后端服务每日凌晨 `00:00` 自动为所有词库运行数据备份（使用 JSON 将词汇集归档），每个词库最多保留最近 3 次的历史备份。
- **预览与一键回退**：用户能随时在前端点击备份节点的“预览”查看快照词汇（只读格式），并提供“回退”功能以一键回滚词库。

## 🛠️ 技术栈说明

- **前端核心**：React 19 + TypeScript + Vite 8
- **前端样式**：Vanilla CSS (毛玻璃拟物化暗黑美学) + TailwindCSS
- **图标系统**：Lucide React
- **后端核心**：Node.js + TypeScript + ts-node
- **实时通信**：WebSockets (带有 3 秒断线重连宽限期和 Ping-Pong 保活)
- **轻量存储**：SQLite3

## 🚀 运行与部署说明

### 前期准备
确保本地安装有 Node.js (推荐 v18+) 环境。

### 1. 安装依赖

进入项目根目录，分别在 `backend` 和 `frontend` 目录执行依赖安装：

```bash
# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 2. 本地开发启动

在不同的终端窗口中分别运行后端服务和前端开发服务器：

#### 启动后端

```bash
cd backend
npm run dev
```
后端默认运行在 `http://localhost:17712`，WebSocket 地址为 `ws://localhost:17712/ws`。

#### 启动前端

```bash
cd frontend
npm run dev
```
前端将默认运行在 `http://localhost:5173`。Vite 已配置反向代理，所有的 `/api` 与 `/ws` 自动转发至后端服务。

### 3. 项目打包构建

如果需要进行生产环境构建：

```bash
# 打包后端 (输出至 dist/)
cd backend
npm run build

# 打包前端 (输出至 dist/)
cd ../frontend
npm run build
```
